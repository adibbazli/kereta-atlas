# Mottokar web

A browser version of Mottokar: a Flask backend that talks to Proton Link, and a React + TypeScript single-page app (Vite) in `frontend/`. The app is built into `static/`, which Flask serves. Python port of `src/providers/proton/*` and `src/providers/demo`.

## Deploy the frontend on Vercel

Set the Vercel project's **Root Directory** to `web/frontend` and use `npm run build` as the build command. Vite writes the Vercel build to `dist/`; regular builds continue writing to `web/static/` for Flask.

## Run

```bash
cd web
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
(cd frontend && npm install && npm run build)   # only after changing frontend/
.venv/bin/python app.py
```

Open http://127.0.0.1:5050. Choose **Demo car** to try a simulated S70 (demo PIN 1234), or **Proton Link 2.0** to sign in with your Proton Link mobile number and password. For frontend work, `npm run dev` in `frontend/` serves on :5173 and proxies `/api` to Flask. Set `BACKEND_SERVER` to change the Vite development proxy target; it defaults to `http://127.0.0.1:5050`.

On macOS's system Python, urllib3 prints a `NotOpenSSLWarning` about LibreSSL. It's harmless: TLS verification still works.

`MOTTOKAR_PORT` changes the port. The server binds to `127.0.0.1` only. Don't expose it to a network: whoever can reach it can unlock and start your car.

## Public access (Cloudflare quick tunnel)

```bash
MOTTOKAR_PUBLIC=1 .venv/bin/python app.py
cloudflared tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:5050
```

cloudflared prints a random `https://….trycloudflare.com` URL, which changes every time it restarts. `--protocol http2` is needed on networks that block QUIC (UDP).

- **Passcode gate:** in public mode, every API request to a tunnel host first needs the **access passcode**. The passcode screen appears automatically.
  - On first start the server generates a passcode and writes it to `instance/passcode.txt` (mode 0600). Set `MOTTOKAR_PASSCODE` to choose your own; changing it locks out every browser.
  - A browser that passes the gate gets a 30-day cookie that is Secure, HttpOnly and SameSite=Strict. "Lock this browser" in the account menu revokes it.
  - Five wrong passcodes per IP in 15 minutes, or 30 from all IPs, lock the gate. Proton sign-in attempts are limited the same way.
- **Unchanged on this computer:** requests to `127.0.0.1` or `localhost` skip the gate.
- **Other hosts:** only `*.trycloudflare.com` is accepted (`MOTTOKAR_PUBLIC_HOSTS` changes this), and POST requests must come from that same `https://` origin.
- **Cloudflare can read the traffic.** TLS ends at Cloudflare's edge, so Cloudflare can see it, including your Proton password when you sign in through the tunnel. For a stable hostname with Cloudflare's own login in front, use a named tunnel with Cloudflare Access.
- **The server is Flask's built-in one,** which is fine for personal use behind the tunnel.
- **State directory:** sessions, gate tokens and caches go in `instance/`. Set `MOTTOKAR_INSTANCE_DIR` to move them; on Vercel (`VERCEL` set) the default is `/tmp/mottokar`, because the deployment is read-only there. Files in `/tmp` are lost whenever the function restarts.
- **Serverless hosts (Vercel):** set `MOTTOKAR_SECRET_KEY` (e.g. `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`) and `MOTTOKAR_PASSCODE`. With the secret set, nothing about sign-in lives on the server's disk:
  - The session record, Proton tokens included, is stored in the `mk_sid` cookie, encrypted with AES-256-GCM. When tokens are refreshed, the next response carries an updated cookie.
  - Gate cookies are signed with an expiry, and they're tied to the passcode.
  - Changing the secret signs out every browser. Changing the passcode locks every browser out of the gate.
  - Sign out and "Lock this browser" only delete the cookie in that browser. A copied cookie stays valid until it expires or the secret changes.

## Install on iPhone (PWA)

1. Open the tunnel URL in **Safari**, enter the passcode and sign in.
2. Tap **Share**, then **Add to Home Screen**. Mottokar opens full screen with its own icon.
3. The installed app keeps its own cookies, separate from Safari's, so enter the passcode and sign in once more inside it.

- **Offline:** the service worker (`sw.js`) caches only the app's own files, so the app opens offline. Car data, sign-in and commands (`/api/*`) always go to the server.
- **Quick tunnel URLs change on every restart.** Each new URL is a new app as far as iOS is concerned, so you would reinstall it. A named tunnel on your own domain avoids this.
- **Icons:** they are generated by `tools/make_icons.py` (dev-only, needs Pillow).

## Deep links and Siri

- `#/do/unlock`, `#/do/lock`, `#/do/horn_lights` and `#/do/windows_close` open a page with a single button for that command. Opening a link sends nothing; the command goes out only after the usual hold.
- The links aren't shown in the app. Use your server's address followed by the path, e.g. `https://<your-tunnel>.trycloudflare.com/#/do/unlock` (or `http://127.0.0.1:5050/#/do/unlock` on this computer).
- **Siri:** make a Shortcut whose only action is **Open URLs**, pointing at the Unlock link, and name it "Unlock my car". Saying "Hey Siri, unlock my car" opens the page; you then hold the button.
- **Safari, not the installed app:** iOS opens Shortcut links in Safari, so sign in there too.
- **No hands-free unlock:** this app doesn't offer it; the hold is always required.

## The app

- **Tabs:** Overview, Controls, Climate, Health, Location. The inbox is behind the bell, and sign-out is in the account menu.
- **Commands:** every command needs a **3-second press-and-hold** (mouse, touch, or holding Space/Enter). Letting go early sends nothing.
- **Toggle buttons:** a single button switches between Lock/Unlock, Open/Close windows, Start/Stop engine and Climate on/off. Its wording and dot follow the car's state: green means secure, yellow means unlocked or open. After a command that was only queued (not confirmed by the car), the state shows as unknown until you refresh.
- **Only supported buttons are shown,** based on the car's capability list. For an S70, that means no Lock trunk, Sunroof, Flash lights only, Defrost or charging.
- **Timers:**
  - The engine runs for 3, 5, 8 or 10 minutes, and the car stops it itself; the app shows a countdown.
  - Climate auto-off is optional: the server sends "climate off" once when the time is up, unless the car is moving, and you can cancel it. Timers live in server memory, so restarting the server loses them.
- **No polling by default:** car data loads once and then only when you press Refresh. Trips, inbox and data plan load the first time you open them.
- **Live mode** (the "Live" switch in the header, off by default):
  - **When it can start:** only while the 12 V battery reads green (12.4 V or more), and not when the car's data plan is below 10%.
  - **What it reads:** it only repeats the status read (`getVehicleStatus`). It never asks the car for its position, sends no commands, and doesn't refresh trips, inbox or data plan.
  - **Measures first:** the first time, it checks whether status reads come from Proton's cloud copy or wake the car. It takes reads 60 s apart, compares the car's update time, and saves the result in `instance/live.json`.
  - **How often:**

    | Result | Driving | Parked |
    |---|---|---|
    | Cloud copy | 30 s | 2 min, backing off to 5 min while nothing changes |
    | Wakes the car, or not yet known | 60 s | 5 min |

  - **One poller per car:** all browsers share one poller on the server, and the server never reads one car more often than every 25 s.
  - **Pauses** while no browser tab is visible, because tabs send a heartbeat only while visible.
  - **Stops by itself** when the battery leaves green, after 30 minutes, after 3 failed reads in a row, or when the session expires. The app shows why.
- **Health:**
  - Fuel shows a bar and %, estimated from the tank size when the car reports litres.
  - Service km, 12 V battery voltage, tyres, data plan, and doors and windows each show a colour cue.
  - "All data from the car" lists every raw field the car sends.
  - A legend lists the colour thresholds.

## What it keeps, and where

| Data | Where | Notes |
|---|---|---|
| Password | Nowhere | MD5-hashed (Proton's scheme) and sent once to `app.acotech.my:8443/app/v1/member/login`, then dropped |
| Access/refresh tokens, device ids | `web/instance/sessions.json` (mode 0600), or the encrypted session cookie when `MOTTOKAR_SECRET_KEY` is set | File entries are keyed by SHA-256 of the session cookie |
| Session cookie | Browser | Random, HttpOnly, SameSite=Strict, 90 days |
| Vehicle PIN | Tab memory by default; browser localStorage (per car) if you tick "Remember on this device"; server memory only while a climate auto-off is pending | Never sent to the server's disk. A saved PIN is removed by "Forget saved PIN" in the account menu, or automatically when the car rejects it. Anyone who can open the app in that browser can send PIN commands |

Sign out deletes the server-side session.

## Hardening

- Requests are refused unless the `Host` is `127.0.0.1:<port>` or `localhost:<port>` (DNS-rebinding protection).
- State-changing requests must be JSON and must come from the same origin (CSRF).
- The CSP allows only same-origin scripts, styles and connections. Images may load from `https:` only (Proton's car renders); `http:` image URLs are dropped.
- All server text is rendered with `textContent`.
- Proton HTTPS calls keep certificate verification on.
- The MQTT broker's certificate is pinned byte for byte, and checked before any byte is sent.
- There are no CDNs, analytics or map tiles. Trip routes are drawn locally as SVG. Map buttons open Google or Apple Maps only when clicked.

## Endpoints this server calls (Proton prod)

- `https://app.acotech.my:8443/`:
  - `app/v1/member/login`
  - `app/v1/member/tokenRefresh`
  - `app/v1/vehicle/flow`
  - `app/v1/vehicle/capability/service/app` (decides which command buttons show; `basic/ability/vehicle/{vin}` is the fallback)
- `https://app-atlas.acotech.my:8443/`:
  - `basic/user/vehicle/list`
  - `basic/ability/vehicle/{vin}`
  - `basic/mat/model/bodyPictureList`
  - `basic/vehicle/checkPinCode`
  - `basic/vehicle/setVehicleName`
  - `iot/function/getVehicleStatus`
  - `iot/function/vehicleControl`
  - `bigdata/vehicle/trip/queryList/app/v1`
  - `bigdata/vehicle/trip/queryTrackList/app/v1`
  - `information/mobileLog/queryLabelList`
  - `information/mobileLog/queryPageList`
  - `information/mobileLog/markReadByLogId`
  - `information/mobileSync/generateDeviceId`
  - `information/mobileSync/integrated/replenish`
- `prodinfomq-atlas.acotech.my:55883` (MQTT over TLS): subscribes to `mobile/<deviceId>/message` and `mobile/<deviceId>/notify` to read command results.
